## Part 1 — Immediate Build Blockers (Nothing Else Can Start)

### 1.1 [BLOCKER] AUTH_USER_MODEL Not Set — Database Cannot Be Migrated

**Sprint affected:** Sprint 1 / Sprint 2
**File:** `config/settings.py`

`AUTH_USER_MODEL = "accounts.User"` is absent from `settings.py`, and `accounts/models.py` contains only Django boilerplate — no `User` model defined. Running `python manage.py migrate` right now would create tables using Django's built-in `auth.User`, making it impossible to swap in a custom user model without resetting the database later.

**What must happen first:**
1. Define `class User(AbstractUser): pass` in `accounts/models.py`
2. Add `AUTH_USER_MODEL = "accounts.User"` to `settings.py`
3. Only then run the first `makemigrations` + `migrate`

**Risk if skipped:** catastrophic — every model with `ForeignKey(settings.AUTH_USER_MODEL)` will be wrong, requiring a full database wipe.

### 1.3 [BLOCKER] Using SQLite Instead of PostgreSQL

**Sprint affected:** Sprint 1 (violated), affects all sprints
**File:** `config/settings.py`

The project uses `django.db.backends.sqlite3`. The plan explicitly states: *"PostgreSQL 15+ — never SQLite, including in dev."*

`Insight.raw_data = models.JSONField(...)` and `UniqueConstraint` with `condition=models.Q(...)` behave differently in SQLite vs PostgreSQL. Tests validated against SQLite may silently pass while production Postgres fails.

**Required actions:**
1. Switch `settings.py` to use `psycopg2` + Postgres
2. Read DB credentials from `.env` via `python-decouple`
3. `createdb spendtracker && createuser spendtracker`
4. Delete `db.sqlite3` — do not commit it

### 2.9 [GAP] `CACHES` (django-redis) Not Configured

**Sprint affected:** Sprint 9/13/14
The Sprint 0 global decisions specify `django-redis` as the cache backend (Redis DB 1, separate from the Celery broker on DB 0). `CACHES` is completely absent from `settings.py`. Without this, `cache.delete(...)` calls in Sprint 14 use Django's default in-memory per-process cache, which will not work correctly in production with multiple gunicorn workers.

Required addition to `settings.py`:
```python
CACHES = {
    "default": {
        "BACKEND": "django_redis.cache.RedisCache",
        "LOCATION": env("CACHE_URL"),  # redis://localhost:6379/1
        "OPTIONS": {"CLIENT_CLASS": "django_redis.client.DefaultClient"},
    }
}
```

## Part 3 — Explicit Stubs & NotImplementedErrors in the Plan

### 3.1 [CRITICAL] `SetuAAClient` Methods Are `NotImplementedError` Stubs

**Sprint affected:** Sprint 14b
**File (to be created):** `integrations/aa_client.py`

`create_consent_request()` and `fetch_fi_data()` ship as `raise NotImplementedError(...)` by design — Setu's API must be confirmed against live sandbox docs. Sprint 14b cannot ship until both are implemented.

**Actions required:**
1. Register at setu.co, obtain `SETU_CLIENT_ID`, `SETU_CLIENT_SECRET`, `SETU_AA_BASE_URL`
2. Implement both methods against current sandbox docs

**Open sub-questions for 14b:**
- How does Setu authenticate its webhook POSTs? Plan says "verify signature per their docs" — mechanism unspecified.
- `consent_webhook` reads `request.POST["consent_handle"]` — what if Setu sends JSON body, not form-encoded? Verify content-type.
- Does Setu sandbox support `MUTUAL_FUND`/`EQUITIES` FI types or only `DEPOSIT`?
- Setu's FI data arrives transport-encrypted. Which keypair decrypts it? The Fernet `FIELD_ENCRYPTION_KEY` is for at-rest storage, not Setu transport encryption. An asymmetric keypair must be registered with Setu separately — not covered in any sprint file.

### 4.2 [DESIGN DECISION] Rate Limiting and `django-axes` Not Assigned to Any Sprint

**Sprint affected:** Sprint 0 global decisions
Sprint 0 specifies: DRF `UserRateThrottle` at `100/min` on write endpoints; `django-axes` lockout after 5 failed logins. Neither is in `settings.py` nor assigned to a sprint. Most logical home: Sprint 2 (auth) or Sprint 16 (security hardening), but neither sprint file mentions them.

---

### 4.3 [DESIGN DECISION] DRF Pagination Not Configured

**Sprint affected:** Sprint 19
Sprint 0 specifies `PageNumberPagination, PAGE_SIZE = 50` globally. Not in `settings.py`. Sprint 19's `test_transaction_list_is_paginated` test will fail without `REST_FRAMEWORK["DEFAULT_PAGINATION_CLASS"]` being set.

---

### 4.4 [DESIGN DECISION] Income vs Expense Sign Convention Undefined

**Sprint affected:** Sprint 3/6/14
`Transaction.amount` is a `DecimalField` with no sign constraint. The CSV importer uses `abs(row["Amount"])`. But:
- Should `amount` always be positive?
- The dashboard's `total_spent` sums all amounts — income transactions would inflate spending totals.
- `Category.kind = INCOME/EXPENSE` exists but `Transaction` has no matching `kind` or `direction` field.

No sign convention is stated anywhere in the plan.

---

### 4.5 [DESIGN DECISION] No Strategy for `Insight` Deduplication / Stale Insight Cleanup

**Sprint affected:** Sprint 10/12/13
Every call to `run_rules_for_user()` creates new `Insight` rows with no deduplication check. The same over-budget condition generates a new row every day, producing a bloated feed.

**Questions unresolved:**
- Use `get_or_create` on `(user, rule_key, category, period_start, period_end)` to deduplicate?
- Auto-expire/soft-delete Insights older than 90 days?
- Add pagination or "load more" to the 10-item feed?

---

### 4.6 [DESIGN DECISION] No User-Facing Views for `FinancialAccount` or `Category` Management

**Sprint affected:** Sprint 3/7/8
`FinancialAccount` is required before any `Transaction` can be created. The plan says "add via /admin/ for early dev." No sprint defines a user-facing CRUD UI for accounts or categories. Non-admin users will be unable to use the app without backend access. `TransactionForm` exposes an account dropdown that will always be empty for users who cannot use `/admin/`.

---

### 4.7 [DESIGN DECISION] `Transaction.is_recurring` Has No Logic or UI

**Sprint affected:** Sprint 3
The `Transaction` model has `is_recurring = models.BooleanField(default=False)`. No sprint defines how it is set, displayed, or used. The `RecurringCreepRule` mentioned in Sprint 10 is not implemented. This field is orphaned in v1.
